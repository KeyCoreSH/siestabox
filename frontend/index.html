O problema operacional

Hotelaria itinerante significa ciclos de transporte, montagem, operação e desmontagem. Cada ciclo vira gargalo.

  • Entrega da chave — sem recepção física, alguém precisa ir até o módulo entregar acesso.
  • Check-out fantasma — o módulo fica marcado como ocupado depois que o hóspede saiu.
  • Manutenção reativa — bateria, temperatura e climatização são descobertas só na reclamação.
  • Precificação manual — cobrança por hora depende de conferência humana.

O que a plataforma responde

Quatro coisas entregues de ponta a ponta, mensuráveis.

  • Liberação remota instantânea — comando unlock via MQTT com ACK do firmware em < 1 s.
  • Estado da porta em tempo real — o firmware notifica aberta, fechada, destravada e travada; o navegador recebe por WebSocket.
  • Precificação por Pix — reserva gera valor, TXID e PIN/QR Code de acesso com validade.
  • Telemetria contínua — bateria, temperatura, umidade, RSSI e uptime gravados para manutenção preditiva.

Integração do pagamento

Nesta versão o Pix é simulado (TXID gerado, reserva marcada como paga) para não exigir credenciais bancárias na avaliação.

  • Trocar por PSP real — implemente POST /api/bookings chamando o provedor (Efí, Mercado Pago, Asaas): crie a cobrança, guarde o txid e confirme o pagamento via webhook antes de liberar o código.
  • Idempotência — bookings.pix_txid é único por cobrança; o webhook atualiza o status, nunca duplica a reserva.
  • Liberação só após pagamento — o código de acesso é criado com expira_em e consumido uma única vez (usado = TRUE).

Firmware MicroPython — pronto para copiar

Código que roda no ESP32 do módulo. Copie direto daqui ou baixe o arquivo. São três arquivos: main.py (lógica), boot.py (inicialização) e config.example.json (parâmetros da unidade).

O firmware conversa com o mesmo broker da API. Ao receber unlock, aciona o relé, publica destravada e responde o ACK — é o que o painel mostra como confirmação em tempo real.

Gravar no ESP32

Com mpremote instalado (pip install mpremote):

terminal 
mpremote connect /dev/ttyUSB0 mip install umqtt.simple
mpremote connect /dev/ttyUSB0 fs cp firmware/main.py :main.py
mpremote connect /dev/ttyUSB0 fs cp firmware/boot.py :boot.py
mpremote connect /dev/ttyUSB0 fs cp firmware/config.example.json :config.json
mpremote connect /dev/ttyUSB0 reset

Sem hardware? Use o simulador

O simulador em Node.js emula os módulos falando MQTT exatamente como o firmware — telemetria, eventos de porta e ACK com latência realista.

terminal 
cd backend && npm install
MQTT_URL=mqtt://127.0.0.1:1883 DOOR_FLAP=1 npm run sim

Como rodar

Três caminhos: stack completa com Docker, desenvolvimento local da API, e firmware no hardware real.

A. Stack completa (recomendado)

terminal 
git clone https://github.com/KeyCoreSH/siestabox.git
cd siestabox
cp .env.example .env
docker compose up -d --build

# Sobe: db (PostGIS), mqtt (Mosquitto), api (Fastify), web (nginx)
# Painel:  http://localhost:8131
# API:     http://localhost:8080/api/health

# Simular os módulos ESP32 falando MQTT:
docker compose --profile sim up -d simulator

B. Desenvolvimento local da API

terminal 
cd backend
cp ../.env.example ../.env
npm install

# Requer Postgres/PostGIS e Mosquitto acessíveis
export DATABASE_URL="postgresql://keycore_admin:senha@localhost:5432/siestabox_db"
export MQTT_URL="mqtt://localhost:1883"

npm run build && npm start     # produção
npm run dev                    # watch mode
npm run sim                    # simulador de firmware

C. Firmware no ESP32

terminal 
# 1. Grave o MicroPython no ESP32 (esptool)
esptool.py --chip esp32 --port /dev/ttyUSB0 write_flash -z 0x1000 ESP32_GENERIC-*.bin

# 2. Instale o cliente MQTT e copie os arquivos
pip install mpremote esptool
mpremote connect /dev/ttyUSB0 mip install umqtt.simple
mpremote connect /dev/ttyUSB0 fs cp firmware/main.py :main.py
mpremote connect /dev/ttyUSB0 fs cp firmware/boot.py :boot.py
mpremote connect /dev/ttyUSB0 fs cp firmware/config.example.json :config.json

# 3. Edite o config.json com Wi-Fi, IP do broker e unit_code
# 4. Reinicie
mpremote connect /dev/ttyUSB0 reset
